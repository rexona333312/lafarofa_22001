# Монтаж обычного видеоряда

Изменения по `reference_analysis/swiss_1019_20261019/editing_without_motion.html`.
Моушн-шаблоны, настройки провайдера Vision и тайминги озвучки сохраняются.

## Что подключено

- Экспорт планировщика содержит `shot_editing_contract`: смысловую цель сцены,
  роли кадров, крупность, темп, видимое действие и связь с предыдущим планом.
  Один `scene_id` объединяет связанные кадры. Контраст и ассоциация требуют
  объяснения `link`; монтажная связь сама по себе не доказывает исторический факт.
- Смежные запланированные кадры одной сцены подбираются последовательно.
  Следующий поиск получает соседние задачи и фактически выбранный предыдущий
  материал, включая сохранённый ручной выбор. Независимые сцены ищутся параллельно.
- Apple оценивает до трёх непрерывных окон каждого видеокандидата. На окно
  извлекаются три кадра: начало, середина, конец. Каждое окно проверяется отдельно,
  затем программа выбирает лучшую оценку и сама назначает его таймкоды.
  Для YouTube-превью окно не пересекает границу склеенных поисковых фрагментов;
  результат переводится во время оригинала. Это не полный просмотр исходника:
  короткое действие и внутреннюю склейку между выборками можно пропустить.
- При успешной проверке выбранный интервал действительно вырезается из файла.
  Короткие вставки менее секунды поддерживаются. Неудачное применение таймкодов
  нового выбора помечается для проверки и не считается релевантным материалом.
- У обычных фото без явного пресета устанавливающий план получает отдаление,
  деталь и передышка — статику. Явный пресет имеет приоритет. У видео сохраняется
  движение исходника. Автоматического ускорения речи/клипа нет.
- Плотность монтажа, спокойные планы и контрасты задаёт план по смыслу речи и
  исходным `word_range`. Отчёт предупреждает о подозрительных длительностях и
  повторах крупности; он не растягивает и не переставляет слова.
- Пустой/отсутствующий `transitions` теперь означает **cut**. Обязательные 40%
  скачанных переходов удалены. Явно выбранные переходы сохраняются, включая мягкую
  подложку под явно заданный screen-overlay. Внутренние стыки моушн-серий не менялись.
- `shot_plan` и `scene_id` сохраняются в проекте, доходят до сборщика и входят
  в `shot_editing` ответа проекта и `render_report.json`. Оценки окон сохраняются
  в метаданных материала как `vision_window_assessments`; связь — как
  `vision_continuity_matches` / `vision_continuity_reason`.

## Как использовать

Перезапустить приложение. Для нового монтажа скачать свежий JSON для Codex,
перепланировать обычные сцены с `shot_plan`, затем импортировать timeline и
запустить поиск. Старые JSON поддерживаются, но их прежние кадры не становятся
новой последовательностью автоматически. При изменении задачи кадра импорт
сбрасывает старый подбор этого и следующих связанных планов. Уже подтверждённые
материалы при продолжении прерванного поиска сохраняются.

```json
{
  "type": "video",
  "scene_id": "precision",
  "query": "watchmaker hands adjusting mechanism close up",
  "word_range": [12, 19],
  "shot_plan": {
    "role": "detail",
    "scale": "detail",
    "pace": "normal",
    "goal": "Показать конкретный механизм точности",
    "action": "Руки устанавливают небольшую деталь",
    "relation": "continue",
    "motif": "precision"
  }
}
```

В полном timeline нужны непрерывное покрытие речи и обычные поля поискового
контракта. Крупности: `wide`, `medium`, `close`, `detail`, `unknown`.
Роли: `establishing`, `action`, `detail`, `reaction`, `consequence`, `contrast`,
`bridge`, `breathing`. Темпы: `calm`, `normal`, `urgent`.

Провайдер остаётся Apple. В fast-режиме до трёх локальных обращений к модели на
видеокандидат, в quality — до шести (описание и оценка каждого окна). Лимит числа
кандидатов сохранён: два/четыре. Платного API для этой проверки нет; затраты —
локальное время и вычисления. При наличии предыдущего кадра добавляется одно
описание этого кадра на пакет и отдельная проверка связи для каждого релевантного
кандидата. Без контекста фото сохраняют прежнее число обращений.

## Проверка и превью

`output/scene_shot_editing/index.html` — подборка монтажных этюдов через основной
сборщик, без новой озвучки. `verification/build.json` — размеры, длительность,
число кадров и полное декодирование MP4. `verification/apple_live.json` — живая
проверка выбора действия на составном локальном исходнике. В первом варианте
общий контактный лист вызвал ошибку номера строки; отдельные оценки окон выбрали
нужный интервал 3,5–5,5 с и отклонили два посторонних сюжета. Один успешный пример
не является измерением общей точности модели. В дополнительной проверке
`verification/apple_continuity_live.json` нужное окно выбрано, посторонние отклонены,
но модель не подтвердила продолжение предыдущего кадра: результат помечен для
проверки. У Apple остаются ложные отказы и ошибки описания; это не проверка
исторического единства события. Первые варианты с совместным показом изображений
или включением прошлого описания в проверку релевантности давали ложные совпадения;
поэтому финальная логика разделяет пригодность кадра и связь между кадрами.

`verification/tests.json` и `tests.log` — результат полного набора тестов;
`latest_tests.json` / `latest_tests.log` — последние профильные проверки после
разделения независимой пригодности и связности.
Известный прежний сбой `test_photo_pan_remotion_keeps_continuous_subpixel_motion`
ожидает вызов Remotion PhotoCamera, тогда как обычная камера уже использует
FFmpeg. В этой задаче её backend не менялся. Проверки реального рендера обычных
фото и явных переходов выполняются отдельно существующими тестами.

`verification/protected_files.json` проверяет неизменность 38 файлов настройки
провайдера и исходников Remotion относительно резервной копии. Копия изменённых
модулей до начала работ: `backups/before_shot_editing_20261020`.

Проверка исходных кадров для превью показала неточность старого описания клипа
86: там люди рассматривают большой лист, а не подтверждённая операция печатной
машины. В демонстрации он не используется как доказательство производства.
