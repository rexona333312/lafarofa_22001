# ИИ-аватар под оригинальную озвучку

Обновлено 8 октября 2026. Обновлённая копия приложения: http://127.0.0.1:5003/.

## Dreamina: текущий процесс

1. Выбери «ИИ-аватар», «Dreamina · отдельное видео под каждую реплику» и язык озвучки (CS — чешский выбран по умолчанию в новом интерфейсе).
2. Загрузи готовую озвучку и подготовь JSON. WhisperX определяет слова и таймкоды один раз.
3. Скачай свежий `luna_input.json` и передай его Codex. Экспорт содержит правила: ориентир аватара 4–5% длительности, цель 4,4%, каждое непрерывное появление до 3 секунд. Реплики выбираются по смыслу, целым словам и естественным паузам.
4. Импортируй `timeline.json`. В боковой панели появится очередь аватарных вставок: номер кадра, начало/конец, длительность и оригинальный текст. Кнопка «WAV и видео Dreamina» в карточке открывает соответствующую вставку.
5. Скачай WAV выбранной реплики. Это фрагмент исходной общей озвучки, PCM 16-bit / 48 kHz, с точными границами кадров финального видео. В панели можно его прослушать. При повторном скачивании используется кэш.
6. Загрузи изображение аватара и этот WAV в Dreamina через Upload audio. Скачай готовое видео и добавь его в ту же вставку. При загрузке софт автоматически увеличивает видео до 110% с обрезкой по центру и сохраняет исходный размер кадра. Если Dreamina обрезала конец и после выбранного начала недостаёт не больше 0,1 секунды, последний кадр кратко удерживается до конца слота. Исходная озвучка, скорость и таймлайн сохраняются; дополнение хвоста указано рядом с файлом. Более длинный клип сохраняет свою длительность. Готовый клип виден в предпросмотре. Увеличение применяется один раз; изменение начала реплики и сборка не увеличивают его повторно. Уже загруженные ранее файлы сохраняются как есть; чтобы увеличить их, загрузи исходный клип заново.
7. Если Dreamina добавила вступительную паузу, укажи «Начало нужной реплики в видео, с». Для уже добавленного видео есть «Сохранить начало». Проверь соответствие губ оригинальному WAV на первом клипе; приложение проверяет длину файла, а не качество lip-sync.
8. Выбери остальные материалы и собери видео. Полная оригинальная озвучка сохраняется. Звук аватарных MP4 выключен; повторной транскрибации и сдвига таймлайна нет.

Для ролика 12–16 минут цель составляет примерно 32–42 секунды аватара: 11–15 вставок около трёх секунд или больше более коротких вставок. Доля — ориентир, отклонение показано в интерфейсе; длительность отдельного непрерывного появления до трёх секунд проверяется при импорте и сборке. Несколько соседних аватарных кадров не позволяют обойти этот предел.

Отдельный клип привязан к конкретной реплике. Общая библиотека не используется как запасной вариант. Лимита в пять клипов для Dreamina нет. Если видео отсутствует, удалено или после выбранного начала недостаёт больше 0,1 секунды, загрузка отклоняется; ошибка видна прямо в слоте. Сборка требует готового видео на всю длину слота. Более длинное видео обрезается, скорость не меняется, циклов нет; удержание последнего кадра используется только для микронехватки при загрузке. По умолчанию стыки говорящего аватара — cut; автоматический crossfade к ним не добавляется.

Назначения сохраняются в `project.json`. Повторный импорт сохраняет назначение, когда у того же кадра совпадают начало, конец, текст и word_range. При смене реплики старое видео не подставляется; загрузи новый клип. Старые файлы сохраняются для предыдущих экспортов.

## Формат таймлайна

В корне нового аватарного таймлайна:

```json
{
  "video_mode": "ai_avatar",
  "avatar_workflow": "dreamina",
  "chunks": [],
  "transitions": [],
  "audio_tracks": [],
  "text_cues": []
}
```

`chunks` должен полностью покрывать озвучку; пустой массив выше показывает только поля корня. Предпочтительны непрерывные `word_range:[first,last_exclusive]`: софт сам привязывает их к исходным словам. Старый формат `start`/`end` также принимается. Длительность аватарного кадра после привязки и округления до 30 fps должна быть не больше трёх секунд.

Аватарный кадр:

```json
{
  "scene_id": 3,
  "type": "video",
  "query": "ведущая",
  "search_mode": "broll",
  "start": 20,
  "end": 22.6,
  "text": "Podívejme se proč.",
  "visual_intent": "аватар обращается к зрителю",
  "editor_note_ru": "Короткий переход к объяснению",
  "template": "avatar_full",
  "avatar": {"clip_id": "auto"}
}
```

`clip_id:auto` в Dreamina означает ожидание собственного видео для этого кадра, а не случайный выбор. Начало нужной речи в загруженном видео задаётся в интерфейсе. Текст выше — пример формата; в реальном плане используется точная реплика текущей озвучки.

Сохраняются три композиции: `avatar_full` на весь экран, `avatar_left` и `avatar_right` для ведущей рядом с фото/видео. В боковых композициях `type`, `query`, `files` и `media_origin` относятся к фону; аватар загружается отдельно в очередь Dreamina. Фон ведущей сохраняется. Отражения видео нет.

ИИ-фото по-прежнему планируются через `media_origin:ai_image` и `ai_prompt`, выгружаются отдельным пакетом промптов и добавляются в нужные кадры. Интернет-поиск для `avatar_full` и ручных ИИ-фото не выполняется.

## Совместимость с прежней библиотекой

Старые проекты без `avatar_workflow` открываются в режиме `library` и сохраняют прежнее чередование до пяти клипов, допустимые смещения и явные `clip_id`. Прежний ориентир 20–25% остаётся только в старом режиме. Новые проекты по умолчанию используют Dreamina; способ подготовки можно выбрать в интерфейсе.

Для переключения старого проекта на Dreamina сначала подготовь таймлайн с появлениями до трёх секунд и `avatar:{clip_id:auto}`, затем импортируй его с `avatar_workflow:dreamina`. Старые длинные вставки автоматически не режутся и не растягиваются.

## Проверка

`test_dreamina.py` проверяет экспорт настоящего WAV и совпадение с оригинальными PCM-сэмплами, привязку видео к репликам, смещения, отказ от слишком короткого файла, восстановление проекта, повторный импорт, больше пяти вставок и новые инструкции планировщику. Генерация в Dreamina выполняется пользователем; приложение не расходует её кредиты автоматически.

Итог проверки этой доработки: 83 теста нового процесса, старого аватарного режима, импорта и загрузки материалов прошли; интеграция Remotion проверила 360 кадров, звук и повторное использование кэша. Проверочный проект `scene_dreamina_check` — синтетические цвета и тоны, не готовый чешский ролик. Экспорт: 181 кадр при 30 fps, 6,033333 секунды для исходных 6,017 секунды, звук аватарного MP4 заглушён. `verification.json` хранит результат.

В общем прогоне есть прежний сбой `test_presets.test_photo_pan_remotion_keeps_continuous_subpixel_motion`: тест ожидает Remotion PhotoCamera, тогда как текущая реализация PHOTO_PAN использует FFmpeg. Такой же сбой воспроизведён на файле из резервной копии до этой доработки; реализация движения фото здесь не менялась.
