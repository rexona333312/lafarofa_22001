# Соответствие материала сценарию · 21 октября 2026

Изменена текущая версия. Проверки выполняются тем же локальным Apple через `fm`.
Новых библиотек, облачных моделей и настроек ключей нет.

## Что изменилось

- Источник сначала независимо описывается по названию/подписи: извлекается имя
  без показа модели желаемого имени. Это предотвращает смешивание запроса
  и источника. Явное другое полное имя с общими словами отклоняется; отсутствие
  подписи само по себе не считается доказательством другого человека.
- Для короткого имени поиск использует уже заданный полный `entity_aliases`.
  Повторный поиск сохраняет этот алиас и не превращает его обратно в короткое имя.
- `required_terms` добавляются к поисковому запросу и сохраняются при его упрощении.
- `work_title` проверяется отдельно от имени исполнителя/автора. В старых
  музыкальных вставках берётся единственное название в кавычках из `visual_intent`.
  Название должно присутствовать в метаданных; другое произведение не подходит.
- Видимый формат проверяется отдельно: портрет, интервью, исполнение, обложка
  пластинки, документ, карта или общий материал. Для такого формата нейтральное
  описание изображения выполняется и в fast: оно не видит желаемого объекта.
  Поэтому сумка с камерами не должна проходить как портрет, а открытка — как
  обложка пластинки даже при совпадении текста.
- Отдельные `subject_match`, `visual_match`, `context_match` сохраняются в assets
  как `vision_match_checks`. Любой `conflict` отклоняет материал независимо от
  общего балла. Неподтверждённое обязательное условие тоже не принимается автоматически.
- Для иллюстрации неизвестная дата допустима, явное противоречие — нет. Для strict
  проверяются необходимые дата/место/событие из плана. Чёрно-белый стиль не доказывает дату.
- Ручная загрузка подтверждает выбранную редактором личность; её заново не пытаются
  определять по лицу. Видимый формат, действие и пригодность всё равно проверяются.
- Старые оценки Apple без новой подписи проверки отмечаются в списке проблем.
  При следующем поиске/ранжировании они проверяются заново; новая оценка
  кэшируется для того же запроса и фактических требований.

Автоматическая замена использует существующий механизм повторного поиска:
до двух повторов quality / одного fast, общий `query_budget` до 6, резерв на
явный fallback сохранён, плохие URL исключаются. Внешний поиск по-прежнему
расходует квоты выбранных источников. Локальных проверок Apple может стать больше.

## Новые поля плана

```json
{
  "query": "Roy Black Du bist nicht allein original performance",
  "entity": "Roy Black",
  "entity_type": "person",
  "entity_aliases": ["Gerhard Höllerich"],
  "search_mode": "exact",
  "work_title": "Du bist nicht allein",
  "required_format": "performance",
  "match_policy": "strict"
}
```

`work_title`: непустая строка до 200 символов. `required_format`:
`person_portrait|interview|performance|record_cover|document|map|general`.
Оба поля необязательны: старые JSON принимаются. Для старых запросов очевидный
формат выводится из portrait/Porträt, interview, single/album/record cover и music_insert.
Нужную профессию/роль, место и эпоху следует указать в существующем `context`;
планировщик получил соответствующую инструкцию. Поля из сценария программа
сама не выдумывает. Явные fallback остаются самостоятельными планами: портрет
исполнителя не наследует требование точной песни и не выдаётся за её исполнение.

Это общие проверки: они применимы к людям, организациям, государствам, войнам,
документам и обычному видеоряду. В тестах есть даты, география и события; реального
нового политического или военного ролика в этой проверке нет.

## Проверка и использование

Отчёт: `reference_analysis/semantic_matching_20261021/index.html`.
До изменения три неподходящих материала из сохранённых проектов принимались;
после они отклонены, три ручные замены приняты. Положительные ручные примеры
проверяют видимую пригодность с подтверждённой редактором личностью, а не
самостоятельное распознавание человека. Ещё четыре контрольные задачи проверяют
обычный пейзаж, отсутствие нужного действия, допустимую неизвестную дату и
противоречащий год. В последней задаче метаданные заданы специально: это тест
правила, не датировка фотографии. Промежуточные неудачные прогоны сохранены.

`output/scene_semantic_matching/scene_semantic_matching.mp4`: 6 секунд, три
принятых изображения, основной сборщик, без озвучки. FFmpeg полностью декодировал
результат без ошибок. Config и исходники Remotion сверены по SHA-256.

Перезапусти приложение и запусти новый поиск. Старые проекты сами не перемонтируются;
для их спорных кадров используй повторный поиск. Сохранённые ручные замены не
перезаписывались. Резерв исходников: `backups/before_semantic_matching_20261021`.

Тесты: `rtk proxy .venv/bin/python -m unittest test_media_matching test_apple_retrieval test_shot_editing test_openrouter test_core -q`.
Полный прогон и диагностика — в отчёте. Одна прежняя проверка PhotoCamera ожидает
Remotion при существующем FFmpeg backend; она не скрыта и не менялась.
Эти задачи не измеряют долю ошибок на 40-минутном ролике и не доказывают достижение
15 минут ручных правок. Apple всё ещё может неверно описать изображение или источник.
