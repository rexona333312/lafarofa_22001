# Контекст проекта для нового чата

Я делаю софт для автоматической сборки документальных видео. Проект находится в `/Users/ilia/Downloads/soft_video/video_assembler`. Я передаю его в новый чат, чтобы продолжить работу без восстановления всей переписки.

## Чего я хочу

1. Я загружаю в софт `timeline.json`, подготовленный Luna на основе озвучки. Софт ищет и выбирает фото/видео для каждого клипа, а затем собирает итоговое видео.
2. Для некоторых клипов в `timeline.json` должен указываться Remotion-шаблон: бумажный фон, поверх него найденное фото или видео в карточке с закруглёнными углами, входящей из-за края кадра и плавно вращающейся с ощущением 3D. Есть три направления входа: сверху справа, снизу слева, снизу. В начале такого клипа автоматически играет мой звук whoosh.
3. Отдельно Luna должна решать, где нужен текст: `accent` для ключевого слова, даты, числа или вывода и `plain` для обычной короткой поясняющей надписи. Не нужно автоматически делать текст на каждом клипе.
4. Текстовые шаблоны я делаю и редактирую вручную в CapCut. Софт должен показать мне **точные слова**, тип вставки, абсолютные начало и конец, длительность и нужное имя файла. Я заменяю текст в своём проекте CapCut, экспортирую видео с альфа-каналом под именем `T001.mov`, `T002.mov` и т. д. и кладу в папку конкретного проекта. После этого FFmpeg накладывает эти файлы на найденный видеоряд в точном интервале.
5. Длительность экспорта CapCut должна совпадать с заданием: клип 4,5 секунды = экспорт 4,5 секунды / 135 кадров при 30 fps; клип 5 секунд = 5 секунд / 150 кадров. До финального рендера софт должен показать недостающие или неверные файлы. Фоновые слои в CapCut при прозрачном экспорте надо скрывать, если они не должны перекрывать видеоряд.
6. Звук внутри акцентной текстовой вставки должен сохраняться и смешиваться с озвучкой. Для простого текста звук по умолчанию выключен. Whoosh от Remotion-карточки — отдельный звук.

## Что уже сделано в коде

- Remotion-шаблон расположен в `assets/remotion/paper_card/`. В `chunk.template` доступны `paper_card_top_right`, `paper_card_bottom_left`, `paper_card_bottom`. В качестве фона по умолчанию используется `assets/paper/paper1.jpg`, материал для карточки берётся из выбранного фото/видео, а `assets/sfx/whoosh.mp3` запускается в начале клипа. См. `assets/remotion/README.md`.
- `timeline.json` поддерживает верхнеуровневый массив `text_cues`. Например:

  ```json
  {
    "text_cues": [
      {"id": "T001", "kind": "accent", "text": "Точная фраза", "chunk_index": 0},
      {"id": "T002", "kind": "plain", "text": "Пояснение", "start": 12.0, "end": 16.5}
    ]
  }
  ```

  `chunk_index` отсчитывается с нуля и означает полную длительность соответствующего клипа. Для части клипа используются абсолютные `start`/`end`. `audio` можно задать явно; иначе он включён для `accent` и выключен для `plain`.
- После импорта таймлайна интерфейс показывает раздел «Текст для CapCut» со статусами вставок. В папке конкретной сцены создаётся `text_overlays/ЗАДАНИЯ_ДЛЯ_CAPCUT.txt`. Туда же нужно положить `T001.mov`, `T002.mov` и т. д. Точный путь к этой папке сообщает интерфейс; не путать её с общей папкой `assets/text_templates/`.
- `text_overlays.py` проверяет существование файла, число кадров, 30 fps и наличие доступного альфа-канала, а `ffmpeg_builder.py` накладывает готовую вставку. HEVC с альфой на этом Mac при прямом чтении FFmpeg терял прозрачность, поэтому перед наложением программа временно преобразует такой файл через `avconvert` в ProRes 4444. Временный файл затем удаляется. Для готового ProRes 4444 конвертация не нужна.
- В `assets/text_templates/testik.mov` лежит **образец** акцентного шаблона с надписью `Default text`. Программа не вставляет этот образец во все клипы автоматически: нужен отдельный экспорт из CapCut для каждого задания. Инструкция: `assets/text_templates/README.md`.
- Тесты на момент реализации проходили: `test_core.py` и `test_text_overlays.py` (52 теста). Демонстрационное наложение есть в `output/text_overlay_demo/preview.mp4`.

## Важный спорный момент: разрешение `testik.mov`

Исходный файл я взял из `/Users/ilia/Downloads/testik.mov` и без изменения скопировал в `assets/text_templates/testik.mov`. Ещё есть `/Users/ilia/Downloads/testik/testik.mov`; в прошлой проверке обе исходные копии и файл в проекте совпадали по SHA-256. `ffprobe` для исходного файла сообщает видео **1620×1080**, HEVC, 30 fps, 5,000 секунды. Я не знаю по одному файлу, почему CapCut записал именно такие размеры. Ранее я ошибочно предложил подрезать его до 16:9; это изменение отменено. Сейчас софт сохраняет пропорции вставки, центрирует её и не подрезает и не растягивает. При обсуждении разрешения следует проверять исходный файл и настройки CapCut, а не предполагать, что пользователь хотел 1620×1080.
