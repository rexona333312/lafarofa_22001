# Video Assembler

Готовая озвучка → локальная транскрибация WhisperX → сцены в Codex → поиск реальных фото и видео → проверка кандидатов → MP4 1920×1080, 30 FPS. Скачанные материалы остаются отдельно в папке проекта. Генерации изображений, аватаров и озвучки в этом процессе нет.

## Запуск

Нужны Python 3.12, FFmpeg/FFprobe и Deno или Node для YouTube. Зависимости включают `yt-dlp` и `yt-dlp-ejs`.

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
# На новой установке создай .env из образца и заполни нужные ключи.
cp -n .env.example .env
.venv/bin/python -m flask --app app run --host 127.0.0.1 --port 5001
```

Открой http://127.0.0.1:5001. После изменения `.env` перезапусти сервер. После ошибки OpenRouter 402 запросы приостанавливаются до перезапуска; проверь именно баланс аккаунта, а не лимит ключа. Существующий `~/whisperx-env` определяется автоматически; другой интерпретатор укажи в `WHISPERX_PYTHON`. Для отдельной установки WhisperX используй `requirements-whisperx.txt`. Прямые зависимости приложения находятся в `requirements.in`, зафиксированные — в `requirements.txt`.

Для Remotion-шаблонов один раз установи зависимости:

```bash
cd assets/remotion/paper_card
npm ci
```

### Что хранится в репозитории

Исходный код, тесты, примеры таймлайнов, документация и ресурсы приложения
находятся в репозитории. Локальный `.env`, виртуальные окружения, `node_modules`,
проекты в `output/`, бэкапы, предпросмотры и кэш карт исключены через `.gitignore`.
Их загрузка на GitHub не выполняется; существующие локальные файлы сохраняются.
Референсные видео и результаты анализа также остаются локальными, кроме правил
аватарного монтажа и небольшого каталога клипов. Отдельные исследовательские и
демонстрационные скрипты могут требовать исходные локальные референсы.
Временные медиа для Remotion создаются при рендере; для предпросмотра в Studio
нужно подставить свои изображения или видео в параметры композиции.

## Настройки Vision

Ключи хранятся только в локальном `.env`; образец без секретов — `.env.example`.

```dotenv
VISION_PROVIDER=apple
OPENROUTER_API_KEY=YOUR_LOCAL_KEY
VISION_PRIMARY_MODEL=qwen/qwen3.7-flash
VISION_FALLBACK_MODEL=qwen/qwen3.8-flash
VISION_CONFIDENCE_THRESHOLD=0.70
VISION_CLOSE_SCORE_MARGIN=0.08
VISION_MIN_SCORE=0.60
YOUTUBE_PUBLIC_SEARCH=1
```

Сначала отбираются кандидаты по метаданным, сущности и ограничениям сцены. В Vision поступает до четырёх кандидатов (обычно 2–4; если найден один, проверяется один). Основной проход выполняет Qwen3.7 Flash. Qwen3.8 Flash повторно проверяет тот же набор только при уверенности в лучшем результате ниже 0,70 или разнице оценок двух лучших сопоставимых кандидатов меньше 0,08. HTTP-ошибка основной модели не запускает дорогую модель. Ошибка повторной проверки оставляет первичные оценки с отметкой о ручной проверке.

`score` — соответствие смыслу и визуальная пригодность; `confidence` — уверенность модели в выводе. Это самооценки модели, а не измеренная вероятность правильности. Оценка, модель, причина повторной проверки и исходные таймкоды сохраняются в `assets.json` и видны в подсказке кандидата.

Фото отправляются уменьшенными до 1280 px. Локальное видео отправляется как MP4 без звука, 640 px, 4 FPS. Qwen не получает обычную страницу YouTube вместо видео: приложение скачивает до трёх коротких окон на каждый ролик. При доступных субтитрах/главах окна выбираются по текстовому совпадению; иначе берутся разнесённые участки. Превью не покрывают весь длинный фильм и могут пропустить нужный момент. Выбранные секунды переводятся обратно в исходный ролик; в FullHD скачивается только нужный отрезок, насколько позволяет источник.

`VISION_PROVIDER=apple` использует локальную Apple Foundation Model через `fm` в macOS 27: фотографии анализируются напрямую, для видео FFmpeg создаёт контактный лист из четырёх кадров. Денежные API не вызываются. Если локальная модель ещё загружается или недоступна, поиск продолжает работать по метаданным. OpenRouter и старый Gemini включаются только явным значением `VISION_PROVIDER`.

## Рабочий процесс

### Готовый проект VarAgent → Remotion по смыслу

В интерфейсе раскрой **«VarAgent → наш Remotion по смыслу»**, вставь путь к папке
проекта и нажми **«Импортировать и подобрать моушн»**. По умолчанию обрабатывается
первая минута до ближайшего существующего стыка; `0` минут означает весь ролик.
Нужны `montage_plan.json`, `transcription.json`, чистые исходники в `vid_img/` и одна
исходная озвучка в корне. Исходная папка не изменяется, результат — новый `output/scene_NNN/`.

Приложение использует монтажный план, сохраняет порядок и границы сцен, приводит
видео к 30 FPS и берёт таймкоды слов VarAgent без WhisperX и поиска материалов.
Установленный и авторизованный **Codex CLI** анализирует речь и описания сцен,
выбирает из существующих Remotion-шаблонов и переходов и заполняет их параметры.
Текст, описания сцен и каталог шаблонов передаются в OpenAI через аккаунт Codex;
исходные аудио и видео планировщику не отправляются. Готовый MP4 в `_READY` не
используется: в нём уже может быть запечён штатный моушн VarAgent. Стилизация финала
не переносится. Длинные исходники обрезаются без ускорения, короткие замедляются,
как в VarAgent; для отсутствующего видео поддержан стоп-кадр из `generated/`.
Модель для этого режима
при необходимости задаётся переменной `VARAGENT_CODEX_MODEL`; по умолчанию — выбор CLI.
Вход в аккаунт: `codex login`.

Шаблоны `video` используют готовые движущиеся сцены. Для шаблонов только `photo`
планировщик может выбрать стоп-кадр из нужной сцены, а карты/сравнения строятся из
данных. Сгенерированная историческая иллюстрация не становится первоисточником.
Сценовые границы не подгоняются под графику: несовместимый план отклоняется и
отправляется на уточнение, максимум три попытки. Озвучка и её тайминг сохраняются.
Затем доступна обычная сборка предпросмотра/финального MP4 с исходными SFX шаблонов.

Кнопка **«Заново подобрать моушн по речи»** повторяет анализ с текущей целевой долей
графики. После ошибки CLI импортированный проект остаётся доступным. Можно скачать
его **JSON для Codex** и загрузить вручную план с `scene_updates`, `text_cues`,
`transitions` через **«Загрузить новый timeline.json»**. Полный обычный timeline с
новыми сценами для этого режима не принимается: материалы и монтаж фиксированы.

В папке результата: `varagent_planner_input.json` — вход модели,
`varagent_motion_candidate.json` — последний кандидат,
`varagent_motion_plan.json` — проверенный применённый план, `timeline.json` и
`project.json` — данные для существующего сборщика. Штатные `.mov` VarAgent
не копируются: графика выбирается заново из наших шаблонов.

Проверка: `.venv/bin/python -m unittest -q test_varagent_import`.

Режим **ИИ-аватар**: отдельные говорящие клипы Dreamina под фрагменты оригинальной озвучки (цель 4–5%, до 3 секунд за появление), экспорт WAV и загрузка видео в конкретные вставки; прежняя библиотека до пяти клипов сохранена для старых проектов. Три композиции Remotion (`avatar_full`, `avatar_left`, `avatar_right`), отключённый исходный звук и отдельные правила планирования для Codex. ИИ-фото генерируются пользователем по выгруженным промптам и загружаются в выбранные кадры. Инструкция, формат таймлайна и проверенные примеры: [AVATAR_MODE.md](AVATAR_MODE.md). Приведённые ниже пропорции Faceless не применяются к аватарному режиму.

1. Загрузи свою озвучку. Приложение сохраняет её и создаёт `luna_input.json` с таймкодами слов. Название оставлено для совместимости; планирование выполняет Codex.
2. Передай этот JSON в Codex. Встроенные инструкции требуют смысловые сцены, конкретный визуальный замысел, идентичность объекта и несколько кадров внутри сцены. Начальная пропорция — **70% фото / 30% видео по длительности**.
3. Загрузи полученный `timeline.json`. Автосборка после поиска отключена: сначала показываются кандидаты.
4. Просмотри фото, проиграй видео, выбери материалы. Кнопка «Найти другие материалы» в окне кадра повторяет поиск только для него. Остальные сцены и сохранённый выбор сохраняются. Можно загрузить свой файл.
5. После выбора материалов нажми «Собрать финальное видео · 1080p». Разрешённые текстовые шаблоны рендерятся автоматически через Remotion из `text_cues`; ручные MOV не нужны. Недостающий кадр остановит сборку с перечнем ошибок. Повторная сборка использует кэш неизменённых сцен, текста и переходов. По умолчанию используются склейки cut. Голос сохраняет исходный уровень. Список компонентов: [Remotion](assets/remotion/README.md).

**После просмотра качества вернись к пропорции 70/30:** её можно изменить в инструкциях для Codex. Фактическое соотношение показывается после поиска и может измениться при замене видео фотографией.

Сохранённые проекты открываются через список проектов. Для новых инструкций можно скачать новый `luna_input.json` из старого проекта без повторной транскрибации.

## Таймлайн и источники

Шаблон **«Представление персонажа»**: `person_intro_left`, `person_intro_center`, `person_intro_right`. Софт вырезает человека из фотографии локально, затем Remotion плавно поднимает его из-за нижнего края и добавляет имя, подпись и стрелку. Установка обработчика: `pip install -r requirements-person-intro.txt` в окружении приложения; API-ключ не нужен. Формат и параметры: [Remotion](assets/remotion/README.md). Пример трёх вариантов: [timeline_person_intro.json](examples/timeline_person_intro.json).

Один `chunk` — один кадр; `scene_id` объединяет кадры одной смысловой сцены. Предпочтителен `word_range: [начало, конец)` по индексам слов: диапазоны должны последовательно покрывать всю озвучку. Приложение само вычисляет точные границы кадров. Старые таймлайны с `start`/`end` продолжают приниматься.

Полезные поля: `text`, `visual_intent`, `query`, `search_queries`, `entity`, `entity_type`, `entity_aliases`, `negative_keywords`, `required_terms`, `source_policy`, `visual_fallbacks`, `match_policy`, `work_title`, `work_creator`, `work_kind`, `required_format`. `illustrative` разрешает другое выступление того же человека; `strict` требует конкретного события/даты. Обязательные признаки не исчезают при упрощении запроса. Не задавай точную дату как обязательную, если подходит иллюстративное видео. Проверка личности, произведения и видимого формата: [SEMANTIC_MATCHING.md](SEMANTIC_MATCHING.md). Память выбранных материалов, проверка настоящего действия в видео и итоговой последовательности: [EDITORIAL_LEARNING.md](EDITORIAL_LEARNING.md).

| source_policy | Источник |
|---|---|
| editorial | Реальные фотографии сайтов через Google Images: ReSerp, затем Bright Data |
| youtube | Публичные YouTube-видео через yt-dlp |
| official | YouTube только из `YOUTUBE_TRUSTED_CHANNELS`; `all` не делает канал официальным |
| archive | Wikimedia Commons для фото; Internet Archive для видео |
| licensed_stock | Pexels, Pixabay, Unsplash — последняя ступень для общего видеоряда |

Для современной политики сначала задавай `editorial` для фото и `youtube` для видео; для хроники можно поставить `archive` первым. Приложение собирает ограниченный общий пул из двух доступных реальных источников по source_policy и ранжирует его перед выбором. Для фото это объединение происходит перед Vision: метаданные сокращают пул до четырёх. Для YouTube предварительный выбор момента внутри источника остаётся отдельным шагом; проверенные отрезки затем сравниваются с остальным пулом. Если реальные источники не подошли, очередь доходит до стоков. Одновременно обрабатываются до трёх кадров; фотографии скачиваются небольшими параллельными группами. Пустой/сломанный источник после трёх ошибок пропускается до следующего запуска.

Стоковые API требуют собственные ключи. ReSerp и Bright Data требуют ключи SERP; у Bright Data также нужна зона `BRIGHTDATA_SERP_ZONE`. YouTube, Commons и Archive не требуют API-ключа. `YOUTUBE_COOKIE_FILE` — необязательный локальный Netscape cookies.txt, если YouTube требует вход.

`YOUTUBE_PUBLIC_SEARCH=1` снимает ограничение только на Creative Commons. Материалы без указанной лицензии не блокируют сборку; страницу источника, автора и лицензию приложение сохраняет, проверку прав выполняет пользователь. Это не подтверждает права автоматически. Закрытые ресурсы, испорченные файлы и известные стоковые превью с водяными знаками по-прежнему отбрасываются.

Фото принимаются от 640×360; архивное видео — от 640×360, обычный сток — от 1280×720. Загрузка атомарная: неполный файл не заменяет рабочий. Лимиты: фото 30 МБ, видео 150 МБ; бюджет загрузки 30/120 секунд соответственно. Поисковый бюджет кадра — до шести запросов, с резервом для явного fallback. Метаданные конкретного ролика, скачивание и Vision считаются отдельно.

Для перехода от видео к фотографии нужен явный `visual_fallbacks` с `type: photo`; новые инструкции Codex это требуют. Если подходящего материала нет, добавь файл вручную: финальная сборка с пустым кадром не запускается. Карта/документ должны иметь собственный смысловой запрос. Новостные видеосайты напрямую не охвачены универсальным загрузчиком: поиск редакционных материалов сейчас работает для фото, видео — через YouTube/Archive/стоки.

Новые смысловые шаблоны: `marker_highlight` — ключевые слова и факты; `question_panel_bottom` / `question_panel_top` — вопросы, противопоставления и выводы. Это `text_cues` с `kind:accent`, длительностью от 1,4 секунды, белым строчным Coolvetica. Маркер рисуется жёлтыми неровными мазками за уже появившейся фразой, слева направо. Его оригинальный `assets/sfx/marker_scribble.mp3` звучит на 30% только во время закрашивания. Красная плашка приходит к центру за 0,7 секунды; виньетка синхронно появляется и исчезает. Фон этих шаблонов не размывается.

`chunk.template:history_timeline` — фотография предмета целиком в рамке над прокручиваемой годовой шкалой. `type:photo`, длительность от 3 секунд, `params:{year:1918,from_year:1913,label:"fishing trap"}`. Только `year` — дата из озвучки; соседние деления вычисляются, факты не добавляются. `from_year` задаёт начало прокрутки, по умолчанию `year-3`; `scroll_frames` 21..180, по умолчанию 72, с резервом времени для появления фотографии. Обязательный пользовательский `assets/sfx/scrolling.mp3` проигрывается на 30% исходной громкости только во время прокрутки; при необходимости повторяется. Дополнительные API и удаление фона для этих шаблонов не нужны.

Готовые примеры: `output/scene_editorial_templates/` — общий 20-секундный ролик и отдельные `marker.mp4`, `panel_bottom.mp4`, `panel_top.mp4`, `timeline.mp4`. Повторная сборка: `rtk proxy .venv/bin/python editorial_templates_demo.py`. Демонстрация использует предоставленные скриншоты; годы 1913 → 1918 повторяют пример композиции и не утверждают дату изобретения предмета. JSON: `examples/timeline_editorial_templates.json`. Новые шаблоны и правила выбора автоматически включаются в следующий экспорт для Codex.

Дополнительные универсальные шаблоны: `impact_typewriter` печатает крупный белый КАПС из 1–4 слов, постепенно окрашивает фон красным и держит результат до конца сцены. Печать и её `typewrite.WAV` на 30% привязаны к интервалам произнесения слов; в паузах SFX не звучит. `speech_words_grid` / `speech_words_overlay` мягко собирают фразу по словам с лёгким свечением, соответственно на чёрной изогнутой сетке или поверх выбранного фото/видео. Для этих трёх `text_cues` используй точную фразу озвучки и `word_range:[first,last_exclusive]` из глобального `word_timestamps`. Софт сам вычисляет кадры; при отсутствии диапазона допускается только единственное дословное совпадение внутри вставки. Сначала нужно подготовить озвучку через WhisperX.

`selective_marker` оставляет фразу целиком и одновременно рисует ручные жёлтые выделения за несколькими её частями. `params.highlight_ranges:[[0,2],[4,6]]` — непересекающиеся диапазоны слов внутри фразы; выбранные части курсивом, весь текст белым строчным Coolvetica. Один оригинальный звук маркера на 30% на всё закрашивание.

Серия фото — 2–5 последовательных `type:photo` chunks с общим `params.carousel_group` и одним оформлением: `photo_carousel_paper`, `photo_carousel_editorial`, `photo_carousel_dark`, `photo_carousel_film`. Первый кадр приходит снизу, следующие сдвигают предыдущие влево, вход по 0,7 секунды. Каждая карточка имеет отдельный смысловой поисковый запрос и выбранное фото. Стыки внутри серии — `cut` (или без явно заданного перехода); дополнительный crossfade запрещён, чтобы не нарушать встроенное перелистывание. `params.archival:true` включает ч/б только для архивной серии; современные фото сохраняют цвет. Для журнального оформления можно задать короткий `caption` из озвучки. Фон бумажной серии берётся от первого chunk, чтобы он не менялся на стыках.

`map_annotations` и `map_geographic` используют реальные координаты из `params.geo`: спутниковая подложка, выделение страны, маршруты и 3D-рельеф. Для нового плана указывай `geo.mode:flat|terrain` и ключевые кадры камеры. Старый режим поверх картинки карты отключён.

Демонстрация всех новых вариантов: `rtk proxy .venv/bin/python narrative_templates_demo.py`. Использует системный локальный голос Samantha и реальное выравнивание WhisperX, без платного TTS API. Результаты: `output/scene_narrative_templates/`, общий ролик и восемь отдельных примеров — четыре текстовых и четыре оформления серий. Фотографии, источники и лицензии сохраняются в `sources.json`, таймкоды — в `aligned_words.json`. Темы примеров: технологии, политика и архивная история.

## Музыкальные паузы в таймлайне

По явной просьбе пользователя можно вставить отдельный `type:video` chunk с `music_insert:true`, `duration:5`, пустыми `text` и `word_range:[i,i]`. Индекс `i` — начало следующего слова в исходном WhisperX JSON. Обычные chunks по-прежнему покрывают все исходные слова ровно один раз. `start/end`, переходы, титры и музыка указываются уже со сдвигом после пауз; исходный `audio_duration` не меняется. Максимум 5 секунд на паузу, максимум 32 паузы; без шаблона и панелей. Для старых таймлайнов поведение прежнее.

Сборщик вставляет тишину в копию PCM-озвучки, сохраняет звук только этих видеовставок, приглушает фоновую музыку до нуля на их время и не изменяет оригинальную озвучку. Первые выбранные 1–5 секунд файла используются синхронно для картинки и звука; для точного припева выберите отрезок через кнопку YouTube либо загрузите готовый клип. Кандидата можно прослушать в окне выбора: для музыкальных вставок исходный звук там включён. Поисковый YouTube-загрузчик сохраняет аудио в этих вставках. Клип без аудиодорожки или короче паузы блокирует сборку с понятной ошибкой. Подставлять фото вместо музыкального фрагмента нельзя.

Проверка: `rtk proxy .venv/bin/python -m unittest -q test_music_inserts`. Тест включает настоящий короткий рендер с разными частотами диктора и исполнения, проверку длительности, неизменность PCM-частей и отклонение беззвучного кандидата.


Монтаж обычного видеоряда: [SHOT_EDITING.md](SHOT_EDITING.md). Новые scene_id/shot_plan связывают кадры, Apple выбирает действие внутри видео по отдельным окнам; пустая дорожка переходов означает cut, квоты эффектных переходов нет. Пример: output/scene_shot_editing/index.html.
